When is buying a GPU cheaper than API inference?

Compare monthly fixed costs with the hosted bill for the same useful work. Count input and output tokens separately because their prices can differ.

2026-11-22

Buy local hardware when its monthly ownership cost is below the hosted bill for the same accepted work and it can meet your busiest deadline. Calculate input and output tokens separately, then compare a quiet month as well as a busy one before committing cash.

Price the computer you would actually buy

On 2026-11-22, NVIDIA's own marketplace listed a GeForce RTX 5090 at $1,999 with 32 GB of GDDR7 memory; the page also showed it out of stock. Budget the card separately and get a current purchasable workstation quote.

A Linux desktop budget also needs the rest of the computer. A Mac budget needs the exact memory and storage configuration you intend to purchase. Do not compare a bare GPU price with a complete Mac or assume equal memory capacity means equal model speed. First choose the local artifact that passes your task and show it fits alongside its working context.

Use straight-line cost allocation for planning: purchase cost minus expected resale value, divided by months of use. For a conservative first estimate, use zero resale value and divide the purchase price by your expected months of use.

Add energy, repairs, administration and financing where they apply. If you already own a suitable computer, calculate incremental operating cost separately from a new purchase. The money already spent is a different decision from cash you would spend today.

Turn real token prices into a job price

Define a job as useful completed work, such as one reviewed repository investigation across several calls. Include repeated context, failed attempts and follow-up answers in its token count. A job's total input tokens do not have to fit in a single context window when they are spread across calls.

hosted_job_cost = input_tokens / 1000000 * input_price_per_million
                + output_tokens / 1000000 * output_price_per_million
break_even_jobs = monthly_fixed_cost / (hosted_job_cost - local_variable_cost)

For the following calculation, use the live catalog's openai/gpt-oss-120b rates fetched on 2026-11-22, rounded to $0.0317 per million input and $0.179 per million output tokens. A job totaling 100,000 input and 20,000 output tokens costs 0.1 × $0.0317 + 0.02 × $0.179 = $0.00675, about 0.68 cents. Check the selected confidential route separately when your data requires it.

Make utilization and deadlines part of break-even

Suppose local variable cost is an illustrative $0.001 per accepted job. The monthly crossover becomes $90 / ($0.00675 − $0.001) = about 15,652.17 jobs, or 15,653 whole jobs. If local variable cost equals or exceeds the hosted job price, there is no spending crossover under this formula.

For energy budgeting, EIA's published US residential average for 2025 is $0.1723/kWh. An illustrative measured 100 kWh per month would cost 100 × $0.1723 = $17.23. Put that into either the monthly overhead or per-job variable cost according to how the machine is used; do not count it twice.

Capacity can rule out an otherwise attractive crossover. Suppose your full pipeline measures two minutes per accepted job. In 160 available hours it can finish 160 × 60 / 2 = 4,800 serial jobs. A financial crossover at 15,653 jobs is irrelevant unless batching, more operating hours or more equipment supplies the missing capacity. Each option changes the budget.

Agent bursts make this particularly visible. Ten agents arriving together share one local GPU's throughput, and requests beyond its active capacity wait in line. Buying enough capacity for the busiest ten minutes can leave it unused for the remainder of the day. Compare both waiting time and monthly spending.

Try it on your workload

Keep one week's job ledger with input tokens, output tokens, retries, accepted results and arrival times. Project a quiet month and a busy month from actual demand rather than multiplying your busiest hour by every hour in a year. Record work that cannot leave the device in a separate category.

As a simple sanity check, an illustrative $90 monthly ownership cost and a hosted job costing about $0.10 reach equality at 900 jobs. Then replace that ten-cent assumption with your measured token mix and fetched prices. Compare the result with the local machine's demonstrated monthly capacity.

Run the same approved examples locally and remotely, scoring answers without seeing their origin. Add review minutes to the ledger. Before buying, obtain an exact hardware quote and replace every assumed ownership figure, including the assumed 36-month lifespan.

How to decide

  • Buy for sustained accepted work that fits the machine and clears the full cost crossover.
  • Rent for irregular demand, occasional larger models and bursts whose local queue is unacceptable.
  • Choose local for a strict offline requirement even when a hosted price is lower.

Rent ten agents for about seven cents before buying more hardware

Ten repository agents working at once on openai/gpt-oss-120b cost about seven cents in tokens on TrustedRouter for the worked jobs. On 2026-11-22, the catalog listed approximately $0.0317 per million input and $0.179 per million output tokens. Each agent consumes 100,000 input and 20,000 output tokens across its investigation, giving 10 × 100,000 = one million input and 10 × 20,000 = 200,000 output. Cost = 1 × $0.0317 + 0.2 × $0.179 = $0.0675, about seven cents.

On one local GPU, those agents share throughput, and requests beyond its parallel capacity wait in line; through a per-token API, independent requests can run at the same time for the same token bill as running them one after another. Compare approved overflow with another fixed monthly hardware expense, using the same accepted-job ledger.

Prices change; check current prices and provider routing, configure your agents and review private API options. Keep local hardware for steady work it handles economically or data that must stay offline.
