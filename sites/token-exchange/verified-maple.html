NYTE Privacy Secured · Evidence for Maple

Maple, checked.
By you, right now.

Maple runs its AI inside a sealed AWS Nitro enclave: hardware that reports exactly what software it is running and signs that report. This page asks the enclave for a fresh report and checks it in your browser. You do not have to take Maple’s word for it, or ours.

Live check

This check runs in your browser and needs JavaScript. Without it, use the manual check below.

  1. Ask the enclave for a fresh attestation

    Your browser picks a random number and sends it to enclave.trymaple.ai. The reply has to contain that number, so it cannot be a recording.

    Waiting

  2. Verify the hardware signature

    The reply is signed by the AWS Nitro hypervisor. Your browser checks the signature and every certificate back to Amazon’s published root.

    Waiting

  3. Compare with Maple’s published approval

    Maple publishes the fingerprint (PCR0) of each release it approves in its open-source repository.

    Waiting

  4. Compare with the build NYTE reproduced

    NYTE rebuilds Maple’s enclave from the public source and records the fingerprint it gets. A match means the running code is the published code.

    Waiting

What NYTE verified

Rebuilt from source.
Not taken on trust.

Before NYTE routes anything to Maple, it rebuilds Maple’s enclave image from the public source code and confirms the result has the same fingerprint Maple approved. It also checks that the source commit is on Maple’s public history and that Maple’s signed approval log is intact. Each new Maple release goes through the same review, and the checks rerun every 30 minutes.

Going through NYTE

The gateway proves itself too.

When a request reaches Maple through NYTE, it first enters NYTE’s own sealed gateway. That gateway is checked here the same way: by asking its hardware what it is running.

Gateway check

This check runs in your browser and needs JavaScript. Without it, use the manual check below.

  1. Ask NYTE’s gateway for its attestation

    Your browser asks api.trustedrouter.com, the address NYTE requests go to, for the signed report from its hardware.

    Waiting

  2. Verify Google’s signature

    The gateway runs in Google Confidential Space on Intel TDX. Google signs a report naming the exact container image running, and your browser checks that signature against Google’s published keys.

    Waiting

  3. Match it to a published release

    NYTE publishes the image of every gateway release it runs, each built from public source. The running image has to be on that list.

    Waiting

  4. Read the Maple fingerprint built into it

    Each gateway release carries the one Maple fingerprint it will talk to. The gateway checks Maple’s attestation itself on every connection and refuses anything else. This step reads that fingerprint from the release’s source.

    Waiting

Check it without this page

Every input is public.

You can repeat both checks with your own tools. Nothing below depends on this website.

# 1. A fresh attestation document from Maple’s enclave (base64 COSE_Sign1)
curl -s https://enclave.trymaple.ai/attestation/$(uuidgen | tr A-Z a-z)

# 2. The fingerprint Maple approved for production
curl -s https://raw.githubusercontent.com/MaplePrivacyLabs/Maple/master/services/opensecret/pcrProd.json

# 3. The fingerprint NYTE reproduced from source, with its evidence
curl -s https://raw.githubusercontent.com/Lore-Hex/quill-cloud-proxy/main/enclave-go/maple-transport/verified-release.json

# 4. NYTE’s gateway attestation: a token signed by Google (decode it with any JWT tool)
curl -s https://api.trustedrouter.com/attestation

# 5. The gateway images NYTE has published, to compare with the token’s image_digest
curl -s https://trust.trustedrouter.com/trust/gcp-release.json

# 6. The Maple fingerprint built into that gateway release. Replace {commit} with the
#    characters after "gcp-release-" in the token’s image_reference
curl -s https://raw.githubusercontent.com/Lore-Hex/quill-cloud-proxy/{commit}/enclave-go/maple-transport/verified-release.json

What this does and does not show.

It shows what is running. A verified result means a genuine enclave answered your browser’s question just now, and it runs the image built from Maple’s published source. The signature proves the hardware and the software, not the network address it answered from. Reading the source is how you learn what the image does with your data.

It covers the enclave, not everything. The checks cover Maple’s front enclave and NYTE’s gateway on Google Cloud, one gateway machine per visit. NYTE routes one Maple model. That NYTE’s published image comes from its public source is NYTE’s record, which you can rebuild to confirm. This is not an audit of Maple’s company, apps, or other systems.

The seal is a link, not a result. The seal image on Maple’s site is static. The result is whatever this page shows when you open it. Maple ships often, so you may see a release that NYTE is still reviewing.
