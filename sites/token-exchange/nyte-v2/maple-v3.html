Evidence for Maple

Maple, checked.
By you, right now.

Maple’s service is fronted by a sealed AWS Nitro enclave: hardware that reports exactly what software it is running and signs that report. This page asks the enclave for a fresh report and checks it in your browser. You do not have to take Maple’s word for what is running.

What NYTE verified

Rebuilt from source.
Not taken on trust.

Before NYTE routes anything to Maple, it rebuilds Maple’s enclave image from the public source code and confirms the result has the same fingerprint Maple approved. It also checks that the source commit is on Maple’s public history and that Maple’s signed approval log is intact. Each new Maple release goes through the same review, and the checks rerun every 30 minutes.

Going through NYTE

The gateway proves itself too.

When a request reaches Maple through NYTE, it first enters NYTE’s own sealed gateway. That gateway is checked here too, by asking its hardware what it is running.

Checking the gatewayGateway check

Waiting for the check above.This check runs in your browser and needs JavaScript. Without it, use the manual check below.

  1. Ask NYTE’s gateway for its attestation

    Your browser asks api.trustedrouter.com, the address NYTE requests go to, for the signed report from its hardware.

    Waiting

  2. Verify Google’s signature

    The gateway runs in Google Confidential Space, on hardware that encrypts its memory. Google signs a report naming the exact container image running, and your browser checks that signature against Google’s published keys.

    Waiting

  3. Match it to a published release

    NYTE publishes the image of every gateway release it runs, and the public source commit it states each was built from. The running image has to be on that list, under the name NYTE published.

    Waiting

  4. Read the Maple fingerprint built into it

    Each gateway release records the one Maple fingerprint it is built to accept. This step reads that record at the release’s own commit. The gateway’s source is where you can read how it checks Maple’s attestation and refuses any other fingerprint.

    Waiting

Check it without this page

Every input is public.

You can repeat both checks with your own tools. Nothing below depends on this website.

Prompt
Follow the manual steps at https://nytokenexchange.com/verified/maple#manual with your own tools, verify every signature yourself against Amazon’s Nitro root and Google’s published keys, trust nothing the page itself claims, and tell me whether Maple’s enclave and NYTE’s gateway are running the published code and what you could not check.

Shell
# 1. A fresh attestation document from Maple’s enclave (base64 COSE_Sign1)
curl -s https://enclave.trymaple.ai/attestation/$(uuidgen | tr A-Z a-z)
# 2. The fingerprint Maple approved for production
curl -s https://raw.githubusercontent.com/MaplePrivacyLabs/Maple/master/services/opensecret/pcrProd.json
# 3. The fingerprint NYTE reproduced from source, with its evidence
curl -s https://raw.githubusercontent.com/Lore-Hex/quill-cloud-proxy/main/enclave-go/maple-transport/verified-release.json
# 4. NYTE’s gateway attestation: a token signed by Google (decode it with any JWT tool)
curl -s https://api.trustedrouter.com/attestation
# 5. The gateway images NYTE has published, to compare with the token’s image_digest
curl -s https://trust.trustedrouter.com/trust/gcp-release.json
# 6. The Maple fingerprint built into that gateway release. Replace {commit} with the
#    characters after "gcp-release-" in the token’s image_reference
curl -s https://raw.githubusercontent.com/Lore-Hex/quill-cloud-proxy/{commit}/enclave-go/maple-transport/verified-release.json

Limits

What this does and does not show.

It shows what is running.

A verified result means a genuine enclave answered your browser’s question just now, and it runs the image NYTE reproduced from Maple’s published source. The signature proves the hardware and the software, not the network address it answered from. Reading the source is how you learn what the image does with your data.

It covers the enclave, not everything.

The checks cover Maple’s front enclave and NYTE’s gateway on Google Cloud, one gateway machine per visit. The gateways NYTE runs on other clouds are not checked here. This is not an audit of Maple’s company, apps, or other systems.

The gateway check proves less.

Maple’s enclave answers a number your browser just picked. The gateway’s token is not made for you: it can be up to an hour old, and it shows that a machine running that image answers at this address, not that your own request lands on it. That the image was built from the named commit, and that the code enforces the Maple fingerprint, are NYTE’s statements. You can test them by reading and rebuilding the source. The token also lists the settings the gateway was started with, which this page does not inspect.

The badge is a link, not a result.

The badge image on Maple’s site is static. The result is whatever this page shows when you open it. Maple ships often, so you may see a release that NYTE is still reviewing.
