How much would an encrypted API cost for your local workload?

Estimate cost using the eligible route's actual input and output prices. A cheap catalog route with a different privacy tier is a different purchase.

2026-11-22

For 10,000 requests averaging 800 input and 200 output tokens, budget eight million input tokens and two million output tokens. The token estimate is 8 × input price per million + 2 × output price per million, using the eligible encrypted route's prices rather than the cheapest catalog listing.

Count complete requests and distinguish route prices

Include system instructions, conversation history, retrieved passages and tool results in input usage. Count every step of an agent loop, including intermediate tool calls and responses. For a local baseline, Ollama reports prompt_eval_count and eval_count; use those as starting measurements, then compare the hosted route's own reported usage.

The pricing.prompt and pricing.completion fields returned by https://api.trustedrouter.com/v1/models are dollars per token. Multiply by 1,000,000 for dollars per million. For example, $0.00000001 per token × 1,000,000 = $0.01 per million tokens. Keep input and output separate because their rates differ.

These three open-weight models were in the catalog on 2026-11-22. Rates below are rounded for planning, and every calculation uses the displayed rates. For confidential inference, use the eligible endpoint rates in the next section.

openai/gpt-oss-20b $0.01 $0.0475 8 × $0.01 + 2 × $0.0475 = $0.175, about 18 cents

Prices change; check current models and provider endpoints. The cheapest token estimate is useful only after the model meets your quality and privacy requirements. A larger number of unusable answers can reverse the ranking.

Price the confidential route you will actually call

TrustedRouter's routing documentation defines provider.min_privacy: "confidential" as a hard requirement for verified provider confidential compute, end-to-end encryption and zero data retention. Check endpoint eligibility and billing path together. Inspect the exact endpoint record, including its billing path.

On 2026-11-22, the DeepSeek-V3.2 endpoint response listed deepseek/deepseek-v3.2@chutes/prepaid with privacy tier 3 and true values for confidential compute, provider E2EE and zero data retention. Its input and output prices each rounded to $1.06 per million. For the same eight million input and two million output tokens, the planning estimate becomes 8 × $1.06 + 2 × $1.06 = $10.60, about $11.

Keep the privacy filter in the actual request. To reproduce the prepaid route comparison, pin Chutes, require confidential inference, set provider.usage to credits, and disable fallback. With the API key configured, run this example from a macOS or Linux terminal:

curl https://api.trustedrouter.com/v1/chat/completions \
  -H "Authorization: Bearer $TRUSTEDROUTER_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "deepseek/deepseek-v3.2",
    "messages": [{"role":"user","content":"Summarize this fictional note: Jo will draft a plan; no date was agreed."}],
    "provider": {
      "only": ["chutes"],
      "usage": "credits",
      "min_privacy": "confidential",
      "allow_fallbacks": false
    }
  }'

Do not lower the privacy setting to make a cheaper estimate work. If the route is unavailable, revise the schedule or choose another approved eligible route and price it separately.

Add retries, rounding and accepted-answer cost

In an illustrative retry scenario, suppose 5% of the 10,000 jobs require one additional call with the same token counts. That adds 500 calls: 500 × 800 = 400,000 input tokens and 500 × 200 = 100,000 output tokens. Using the rounded confidential rates, the revised estimate is 8.4 × $1.06 + 2.1 × $1.06 = $11.13, about $11.

TrustedRouter's published retail rates already include the standard markup and price floor; do not add the markup again. Standard prepaid billing rounds each input, output and cache component separately to whole microdollars, half up, and applies a one-microdollar minimum to a billed request with positive chargeable usage or a positive fee. One microdollar is $0.000001. Route-specific fees and minimums also matter.

For a tiny illustrative request at $0.01 per million in both directions, ten input and ten output tokens cost 0.1 + 0.1 = 0.2 microdollars before rounding. Both components round to zero, but the positive-usage request minimum makes the charge one microdollar. Compare aggregate estimates with the reported charges from a sample run.

Keep cached and ordinary input separate when the selected route publishes a cache rate. Start with no cache savings unless you have measured applicable usage. If the $11.13 scenario yields 9,500 accepted answers, estimated inference cost per accepted answer is $11.13 ÷ 9,500 = about $0.00117, or 0.12 cents. Add review time and local operating cost as separate lines instead of hiding them inside token prices.

Try it on your workload

Take 100 representative fictional jobs and run a paid sample on the exact approved route. Save input tokens, output tokens, retries, accepted answers and the reported charge. The documented usage.cost_microdollars and usage.total_cost_microdollars fields express known charges as integer microdollars; treat an omitted cost as unknown.

Scale the sample by job type, keeping short extraction calls separate from long agent sessions. For the original exercise, verify that 10,000 × 800 = 8,000,000 input and 10,000 × 200 = 2,000,000 output. Replace those averages with measured values before treating the estimate as a budget.

On one local GPU, concurrent agents share its throughput, and requests beyond its parallel capacity wait in line. Compare with running the same accepted jobs locally: measured electricity, hardware allocation and operating time. Using existing hardware during otherwise idle hours has different economics from buying a dedicated machine. Keep the quality threshold and completion deadline identical.

How to decide

Use the route-specific bill per accepted answer to compare options. Stay local when your machine meets the deadline and data rules favor it. Rent inference for approved bursts when additional hardware would sit idle between jobs. Investigate any sample bill that differs materially from the estimate before scaling the workload.

Run ten agents together for about 16 cents

Ten agents processing independent job batches on qwen/qwen3-32b cost about 16 cents in tokens on TrustedRouter. In this illustrative workload, each consumes 100,000 input and 20,000 output tokens. On 2026-11-22, catalog rates rounded to $0.100 per million input and $0.301 per million output tokens. Input = 10 × 100,000 = 1,000,000; output = 10 × 20,000 = 200,000. Cost = 1 × $0.100 + 0.2 × $0.301 = $0.1602, about 16 cents.

On one local GPU, these agents share its throughput, and requests beyond its parallel capacity wait in line; through a per-token API they can run at the same time, with the same token bill as running them one after another. Divide the existing workload among workers and record usage for every loop. Doing ten times as much work or repeatedly sending duplicated context increases the token volume.

Prices change; check the model catalog and agent setup. Use confidential routing for approved private work and substitute its eligible route prices. Local remains better when existing hardware meets your deadline and the work must stay on the device.
