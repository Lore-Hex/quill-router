Two hosts: inference and account management

Use the attested gateway for inference and the control plane for key management. Both accept Authorization: Bearer <API key>; key management requires a management key.

HostWhat it serves
{{ api_base_url }}Inference: POST /v1/chat/completions, /v1/responses, /v1/messages, /v1/embeddings, images, and videos. Also GET /v1/models and GET /v1/key (inspect the current key).
{{ control_plane_api_base_url }}Account management: POST /v1/keys and GET /v1/keys; GET, PATCH, and DELETE /v1/keys/{hash}; credits, activity, and workspaces. GET /v1/key also works here.

Management calls to the inference host return 404. For example, list your keys on the control plane:

curl {{ control_plane_api_base_url }}/keys \
  -H "Authorization: Bearer $TR_MANAGEMENT_KEY"

Keep management keys on your server. Use an inference key in your model client.

New York Token Exchange API

Use https://api.nytokenexchange.com/v1 as an alternate inference base URL. It accepts the same TrustedRouter API keys, request arguments, provider controls and streaming formats. Requests use your existing balance and key limits. Key creation and account management remain at {{ control_plane_api_base_url }}.

Every trustedrouter/ model also accepts the nyte/ prefix: nyte/auto, nyte/fast, nyte/zdr, nyte/confidential and named combination models. These are alternate names, with identical routing and billing. The catalog keeps one entry per model and lists aliases in trustedrouter.aliases.

For confidential-only inference, use https://api.confidential.nytokenexchange.com/v1 and include provider.min_privacy: "confidential". This endpoint rejects missing or weaker privacy settings and unsupported operations. It requires verified provider-side confidential compute, end-to-end encryption and explicit zero retention, and fails closed when no qualifying route is available. The ordinary endpoint does not impose this privacy floor.

curl https://api.confidential.nytokenexchange.com/v1/chat/completions \
  -H "Authorization: Bearer $TR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"nyte/auto","messages":[{"role":"user","content":"Hello"}],"provider":{"min_privacy":"confidential"},"stream":true}'

Use GET /v1/models for discovery and /attestation on either API hostname for gateway verification. See the trust center and the spot exchange quickstart.
