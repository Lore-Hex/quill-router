Choose the provider connection, then the model

OpenCode separates the agent from the model provider. Connect credentials, select a model and test the tools your coding workflow needs. With TrustedRouter, the gateway key and endpoint stay the same as you compare available model routes.

Use the current OpenCode provider documentation for your installed version. Configuration has changed across versions; the example below follows the current providers and package format. Do not mix it with older provider and npm examples.

Configure a TrustedRouter API key

Set TRUSTEDROUTER_API_KEY in your environment without committing its value. Add the following provider definition to your OpenCode configuration. Replace AUTHOR/MODEL with an exact ID from the current catalog.

{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "trustedrouter": {
      "name": "TrustedRouter",
      "env": ["TRUSTEDROUTER_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {"baseURL": "https://api.trustedrouter.com/v1"},
      "models": {"AUTHOR/MODEL": {"name": "My selected model"}}
    }
  }
}

Select the configured model with /models. OpenCode's provider prefix identifies this connection; the model ID inside the configuration must identify the route you intend to call. Verify the selected model before starting a coding task.

OpenCode with DeepSeek, Kimi or GLM

Choose a route that supports your required tool calls and context. Start with a short response, then ask the agent to inspect a small test project and make one reversible change. Confirm that tool results are returned correctly and that the model can recover after a failing test.

Compare DeepSeek, Kimi and GLM using the same coding scorecard. A large context window is useful only if the agent can use it effectively. Review precision, privacy and current price on the model's endpoint page instead of assuming all hosts serve the same configuration.

Moving from OpenCode with OpenRouter

Create a separate TrustedRouter connection first so you can compare behavior before replacing a working setup. The new gateway needs its own key and base URL. Model identifiers and available features can differ even where both services expose an OpenAI-compatible interface.

Check authentication, streamed output and a complete tool interaction. Compare billed tokens and successful tasks, not just the advertised input rate. See TrustedRouter vs OpenRouter and the pricing comparison method.

Keep the privacy boundary explicit

The coding agent reads project context and the selected provider processes inference. An attested gateway does not remove those components. Inspect route privacy controls and choose an eligible confidential route when required.

If a request fails, first check the installed OpenCode version, package name, endpoint URL and model ID. Do not paste the secret into a public issue. Share a redacted error and configuration shape instead. The agent setup guide provides an independent API smoke test to separate a credential problem from a client integration problem.

Documentation reviewed November 20, 2026. Model availability, client features and pricing can change. Selection advice is an evaluation framework, not a claimed benchmark result.
