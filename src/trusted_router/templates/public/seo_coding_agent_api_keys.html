Connect your key to the client that will use it

For Codex, configure a named provider with its endpoint and the environment variable holding your gateway key. For Cursor, start in Settings → Models and choose the provider supported by your installation. The same workspace can use both clients, each with its own connection settings.

Try one small task before moving a project. Ask the agent to read a fixture and report its first field. Check that the chosen model answered and that the tool result came back into the conversation. That gives you a working reference when you later change providers, keys or models.

Codex API key and custom provider configuration

Codex supports custom provider configuration. The example below selects a Responses-compatible gateway and reads the credential from the environment. Replace the model placeholder with a currently available route; merge the settings into your existing configuration instead of overwriting it.

model = "AUTHOR/MODEL"
model_provider = "trustedrouter"

[model_providers.trustedrouter]
name = "TrustedRouter"
base_url = "https://api.trustedrouter.com/v1"
env_key = "TRUSTEDROUTER_API_KEY"
wire_api = "responses"

Check the official Codex configuration reference for your version. A compatible gateway does not imply support for every OpenAI-hosted tool or transport. Test the specific agent features you use before migrating.

Codex with OpenRouter or another gateway

Use a separate provider name for each connection, and pair its base URL with the corresponding credential. A gateway key does not transfer between services. Compare the same task and explicit model ID where both catalogs offer it; preserve the working configuration until the new route passes your checks.

Our gateway comparison covers the broader choice. Use cost per accepted patch to assess value rather than comparing one input-token price.

Cursor API keys and custom endpoint limits

Cursor documents key setup under Settings → Models. Its API key guide says custom keys cover chat models, while Tab completion keeps using Cursor's built-in models. It also explains that requests pass through Cursor's backend for prompt construction and that its own ZDR policy does not apply to BYOK traffic.

For Cursor with OpenRouter, DeepSeek or TrustedRouter, confirm that your installed version exposes a suitable custom endpoint and supports the model's request format. Do not assume a generic key field accepts every gateway or enables every editor feature. If the required custom endpoint is unavailable, use a supported client such as OpenCode.
