One model name. Different serving formats.

A provider may serve a model in BF16, FP8, INT4, or a mixed format. Those choices matter when comparing output quality, memory use, speed, and cost. The model name alone leaves part of that comparison missing.

TrustedRouter publishes reviewed precision metadata for selected endpoints, linked to the serving code and pinned model configuration. Start with a model's provider list and follow the evidence.

Evidence you can inspect.

The primary weight format, mixed-format details, and KV-cache dtype are separate fields. The metadata includes the review date and source links so an evaluator can see exactly what was reviewed.

Unreviewed precision remains null. Unknown is more useful than an inferred answer presented as fact.

Keep the proof in scope.

runtime_verified is false. A published serving configuration is not per-request proof of loaded weights or precision, and gateway attestation alone cannot establish an upstream model's identity.

Quantization metadata is available; provider.quantizations filtering remains an explicit 501. Compare the evidence before choosing a route.

Why does the same AI model give different results across providers?

The model name is only one part of a deployment. Check the checkpoint revision, weight format, KV-cache precision, tokenizer and prompt template, context handling and generation settings. A change in any of these can affect results. Sampling also produces variation even when the configuration is unchanged.

For DeepSeek, Qwen, Kimi or any other open-weight model, compare the exact provider endpoints rather than assuming a shared family name guarantees identical serving behavior. Pin the provider and keep a dated configuration record before evaluating task quality.

BF16, FP8 and INT4: choose with an evaluation

Lower-precision formats can reduce memory requirements and change serving economics. Their quality impact depends on the model, quantization method and workload. A disclosed lower-precision route can be a good choice; neither a format label nor price alone tells you which route performs best on your task. Keep weight formats separate from cache formats, and test long-context and tool-use behavior if those matter to your application.

Disclosure and verification answer different questions

Model Equality Testing (ICLR 2025) found output-distribution differences between some tested commercial endpoints and reference Llama weights. Those Summer 2024 results illustrate a measurement problem, not a verdict about a provider's current service or evidence that every difference is deception.

TrustedRouter's reviewed precision metadata helps make configuration differences visible. It does not claim to measure every request's weight files. For the next layer, use the model verification checklist and learn how attestation can bind a serving workload to approved artifacts.
