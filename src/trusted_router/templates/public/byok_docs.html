Bring your own upstream provider key

BYOK lets TrustedRouter use a provider credential from your workspace for inference. Your upstream provider account supplies the key; your TrustedRouter key authenticates requests to TrustedRouter. Uploaded secrets are encrypted, and list responses return key metadata and hints rather than the secret.

Management base URL: https://trustedrouter.com/v1. BYOK registration and workspace/key management belong to the control plane. https://api.trustedrouter.com/v1 serves inference; management calls there return 404 because the services are separated. The compatibility endpoints /v1/byok and /v1/byok/{id} are unsupported stubs; use /v1/byok/providers and its key endpoints below.

Authenticate management calls with Authorization: Bearer $TRUSTEDROUTER_MANAGEMENT_KEY, using a management key for the workspace (or a signed-in management session). An inference key or delegated scope does not grant management access. Wallet-only accounts cannot register provider credentials; use an account eligible for BYOK registration.

List providers and keys

curl https://trustedrouter.com/v1/byok/providers \
  -H "Authorization: Bearer $TRUSTEDROUTER_MANAGEMENT_KEY"

curl https://trustedrouter.com/v1/byok/providers/openai/keys \
  -H "Authorization: Bearer $TRUSTEDROUTER_MANAGEMENT_KEY"

GET /v1/byok/providers/{provider} returns one configured provider. Choose a provider that supports BYOK; the provider slug must match the catalog.

Create or update a key

curl https://trustedrouter.com/v1/byok/providers/openai/keys \
  -H "Authorization: Bearer $TRUSTEDROUTER_MANAGEMENT_KEY" \
  -H "Content-Type: application/json" \
  --data '{"api_key":"YOUR_UPSTREAM_OPENAI_KEY","label":"production","fallback_to_credits":false}'

POST /v1/byok/providers/{provider}/keys returns 201 with the new key's metadata under data. Save data.id for updates and deletion. The first key becomes the provider's default. PUT /v1/byok/providers/{provider} sets the default key while preserving other keys; PATCH /v1/byok/providers/{provider}/keys/{key_id} updates a key.

Optional policy fields include label, models (model-ID patterns), priority (lower values first), disabled, and fallback_to_credits. Setting fallback_to_credits: false prevents a request that key can serve from falling back to platform credits. For Amazon Bedrock, Google Vertex, and Azure, use the provider-native credential object instead of a plain API key; see the request schemas in the OpenAPI specification.

Use BYOK at inference

Send inference to https://api.trustedrouter.com/v1 with a TrustedRouter inference API key from the same workspace. Do not send the upstream key as the bearer token. On ranked text routes, eligible configured BYOK keys are considered before credits within each model, unless the request specifies a provider order. Images, video, embeddings, and decisions keep catalog order and may use credits first. Set provider.usage: "byok" to explicitly restrict the request to BYOK. Key model patterns, priorities, disabled status, and provider filters still apply.

curl https://api.trustedrouter.com/v1/chat/completions \
  -H "Authorization: Bearer $TRUSTEDROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{"model":"openai/gpt-4o","messages":[{"role":"user","content":"Hello"}],"provider":{"only":["openai"],"allow_fallbacks":false,"usage":"byok"}}'

Choose a current BYOK-capable model from the catalog. You can also require provider.min_privacy; see provider routing and privacy controls.

Delete a key or provider configuration

curl -X DELETE "https://trustedrouter.com/v1/byok/providers/openai/keys/$BYOK_KEY_ID" \
  -H "Authorization: Bearer $TRUSTEDROUTER_MANAGEMENT_KEY"

curl -X DELETE https://trustedrouter.com/v1/byok/providers/openai \
  -H "Authorization: Bearer $TRUSTEDROUTER_MANAGEMENT_KEY"

Deleting a key removes that stored credential. Deleting the last key removes the provider configuration; deleting the provider removes all its keys. These calls do not revoke the credential at the upstream provider.
