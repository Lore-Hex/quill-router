Credential handoff

Keys travel separately.

The marketplace application is non-secret business and technical information. Once accepted, create a dedicated production credential restricted to model discovery and inference.

  • Use a revocable key created only for TrustedRouter.
  • Exclude account administration, billing, user management, and key creation permissions.
  • Deliver it only through the secure channel arranged during review.
  • Never place the key in email, support tickets, documents, chat, source code, or the catalog response.
Provider Reliability Contract v2

Copy this output exactly.

Do not design a custom catalog or pricing format. Return one unpaginated JSON document from GET /v1/models. Put capabilities, prices, lifecycle, model deadlines, regions, and overload semantics in the machine-readable response.

  • Use exact decimal strings. Every price is USD per one million tokens. Use "0.50", never a JSON float.
  • Use null when a cache rate does not apply. Do not omit required fields.
  • Use lowercase stable IDs. The format is provider/model-name. Never recycle an ID for a different model.
  • Use UTC timestamps. Lifecycle timestamps use RFC 3339, for example 2026-08-05T00:00:00Z.
  • Use one row per billable tier. If rates or capabilities differ, publish a distinct stable model ID for that tier.
  • Separate overload from account quota. Return 503 for temporary serving capacity, 429 for request rate limits, and a stable account-quota error code when TrustedRouter must provision more quota.
  • Always send Retry-After. Fast, explicit backpressure lets TrustedRouter roll over immediately instead of letting requests hang.
  • Publish model deadlines. First-token, completion, and stream-idle budgets are evaluated per model rather than with one global timeout.

Open-source preflight

Check your integration before you apply.

Run the TrustedRouter provider checker against the same production API base you plan to submit. It validates catalog discovery, advertised model callability, non-streaming chat semantics, and streaming behavior against the contract consumed by TrustedRouter.

  • Tiers 1–4 are the conformance gate. A hard failure exits with status 1, so the checker works in CI.
  • Credentials stay local. Use TR_PROVIDER_API_KEY to keep the key out of shell history. Reports recursively redact it.
  • Checks make real requests. The model sweep and chat probes use real, billable completion calls. The default sweep is bounded to 25 advertised models.
  • Keep the report. Attach the redacted JSON artifact to your application so failures can be reproduced quickly.

Acceptance check

These two calls must work.

The catalog request must match the published schema. The chat request must return a normal OpenAI chat completion with nonzero token usage.

  • HTTP 200 with Content-Type: application/json
  • choices[0].message.content contains PONG
  • usage.prompt_tokens, usage.completion_tokens, and usage.total_tokens are integers
  • The response model identifies the model that actually ran

If your API cannot implement this contract, email the same address with the incompatibility. Do not invent a second format.

Contract v1 covers chat-capable models. Include embeddings, image generation, audio, or other APIs in the email and we will map them separately.
