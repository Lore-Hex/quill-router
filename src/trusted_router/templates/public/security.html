Chutes requests are encrypted to the measured GPU workload.

For Chutes TEE routes, the gateway obtains fresh workload evidence and verifies Intel TDX, NVIDIA confidential-computing claims, the pinned workload measurements, and the exact per-instance encryption key inside the TrustedRouter enclave. Only then does it encrypt the request with ML-KEM-768 and ChaCha20-Poly1305.

The verifier sends NVIDIA GPU evidence to nras.attestation.nvidia.com and fetches Intel TDX collateral from api.trustedservices.intel.com. Prompt and output content are not sent to either attestation service.

If evidence, measurements, freshness, or ciphertext authentication fails, that instance is rejected. The gateway may try another attested instance, but it never falls back to plaintext Chutes transport.

Honest limitations

TrustedRouter can verify the hosted gateway path and reduce what the control plane can see. It cannot make every upstream model provider confidential. Provider retention and training claims remain provider specific.

The opt-in Batch API uses temporary encrypted artifact storage backed by GCS, Cloud KMS, and an image-pinned IAM policy. That is a different trust and retention boundary from ordinary content-stateless inference. Review it before submitting sensitive batches.
