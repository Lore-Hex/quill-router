Quick start

OpenCode lists TrustedRouter as a built-in provider.

  1. Create a key in Console → API Keys; TrustedRouter inference keys start with sk-tr-.
  2. Run /connect in OpenCode, choose TrustedRouter, and paste the key.
  3. Run /models and choose {% if opencode_aliases|selectattr("model.id", "equalto", "trustedrouter/zdr")|list %}trustedrouter/trustedrouter/zdr{% else %}a model from the catalog{% endif %}.
/connect
/models

TrustedRouter gives OpenCode one key across 600+ models and 100+ providers, provider fallback and per-key spend limits.

Set a TrustedRouter API key in OpenCode

Use /connect to save a key, or set TRUSTEDROUTER_API_KEY on the OpenCode server process.

MethodCommand
MethodTUICommand/connect → TrustedRouter → API key
MethodCLI key methodCommandopencode auth login trustedrouter --method key
MethodStandalone environmentCommandTRUSTEDROUTER_API_KEY="YOUR_KEY" opencode --standalone
MethodShared service environmentCommandopencode service set env TRUSTEDROUTER_API_KEY YOUR_KEY
MethodVerify connectionsCommandopencode auth list

A saved account wins over an environment connection for the same integration. V2 saves credentials in the server's SQLite database, usually ~/.local/share/opencode/opencode.db, and imports supported credentials from 1.x's ~/.local/share/opencode/auth.json. Use opencode debug paths db to find the actual V2 path. See OpenCode connections.

OpenCode itself does not require an OpenCode key; you connect a provider key, here a TrustedRouter key.

Why is it trustedrouter/trustedrouter/zdr?

The first trustedrouter is OpenCode's provider ID. Everything after the first slash, trustedrouter/zdr, is the model ID sent to TrustedRouter.

Which alias should I choose for coding?

Start with trustedrouter/cheap for inexpensive trials, trustedrouter/zdr for ZDR routes, or trustedrouter/synth-code for code-tuned synthesis.

Use trustedrouter/e2e when all eligible routes must provide verified confidential compute, provider E2EE and explicit ZDR. Synth makes several model calls per request, so it costs more than a single-model request. See agent setup and Synth.

Keep the agent's bill bounded

Create a dedicated key with daily and monthly limits, budget_strict: true and budget_alert_only: false.

Strict mode counts outstanding estimates; actual charges can exceed an estimate. See spend controls and cheaper models, caching and Batch.

OpenCode API key not working

Check the saved account first, then the server environment and installed configuration generation.

SymptomFix
SymptomKey belongs to a different providerFixConnect a TrustedRouter key under TrustedRouter; a DeepSeek or OpenRouter key belongs to that provider's connection.
SymptomShared service still has the old keyFixopencode service set env TRUSTEDROUTER_API_KEY YOUR_KEY stops the running service; the next command starts it with the new value. See OpenCode connections.
SymptomNew environment key ignoredFixA saved account outranks the environment variable. Inspect opencode auth list and manage the saved account with /connect.
SymptomEmpty API keyFixAn unset {env:NAME} becomes an empty string. The V2 full form uses env plus a connection instead of substituting settings.apiKey.
Symptom404 or wrong endpointFixUse {{ api_base_url }} as the base URL; append /chat/completions only for curl.
SymptomModel missingFixAdd the exact catalog ID under the provider's models map, then run opencode models.
SymptomHand-migrated 1.x config failsFixV2 renames provider/npm/options to providers/package/settings. An AI SDK package needs the aisdk: prefix, such as aisdk:@ai-sdk/openai-compatible; a native OpenCode package does not. See migration notes.

For direct DeepSeek and OpenRouter routes, use DeepSeek in OpenCode: three routes.
