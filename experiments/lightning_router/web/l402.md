# L402 funding

Fund a new or existing TrustedRouter API key with Bitcoin over Lightning.
This is optional. The QR checkout at https://lightningrouter.ai/ is unchanged.
No account is created until payment is verified and settled.

Endpoint: `POST https://lightningrouter.ai/api/l402/funding`

[Funding OpenAPI](https://lightningrouter.ai/funding-openapi.json) is separate
from the read-only discovery API. Only call payment operations with the user's
authorization. Never send prompts to this endpoint.

## 1. Choose the destination and amount

Send these headers on the initial request and every retry:

- `X-API-Key`: the existing key to fund, or a new key generated below.
- `Idempotency-Key`: 32 lowercase hexadecimal characters, unique per purchase.
- `Content-Type: application/json`.

The JSON body contains `usd_cents` (integer from 1 to 100000) and `new_account`
(boolean, default false). Set `new_account=true` only for a newly generated key.
For an existing key, leave it false. This does not create a separate account.

For a new account, generate the destination key locally using 32 random bytes:

```python
import secrets
import uuid

api_key = "sk-tr-v1-" + secrets.token_urlsafe(32)
idempotency_key = uuid.uuid4().hex
```

Save both securely before requesting an invoice. This key is the only way to
recover your credits. Do not print it to shared logs or generate a replacement
on retry. There is no account until the invoice settles.

Example with securely stored environment variables for an existing key:

```sh
curl --silent --show-error --include \
  https://lightningrouter.ai/api/l402/funding \
  -H "X-API-Key: ${TRUSTEDROUTER_API_KEY}" \
  -H "Idempotency-Key: ${FUNDING_REQUEST_ID}" \
  -H 'Content-Type: application/json' \
  -d '{"usd_cents":1000,"new_account":false}'
```

Do not use `--fail`: HTTP 402 is the expected payment challenge, not an outage.

## 2. Review and pay the challenge

An unpaid invoice returns HTTP 402 with the standard header:

```text
WWW-Authenticate: L402 macaroon="...", invoice="lnbc..."
```

The JSON also contains `macaroon`, `bolt11`, `id`, `usd_amount`, `invoice_btc`,
`requested_msat`, `expires_at`, `fx_margin_bps`, and `proof_expires_at`.
Verify the signed invoice's amount, network and expiry in your wallet before
paying. Pay the invoice once and retain the successful payment's 32-byte
preimage. Do not send an on-chain Bitcoin transfer.

The existing 10% FX buffer applies. For $10 in credits, the BTC invoice is worth
about $11.11 at the locked Coinbase spot quote. Your wallet may charge a separate
routing fee. Credits and inference charges stay in USD. A retry preserves the
original invoice and quote, not a new exchange rate.

## 3. Retry with payment proof

Retry the same POST with the same body, `X-API-Key` and `Idempotency-Key`, adding:

```text
Authorization: L402 <macaroon>:<64-character hexadecimal payment preimage>
```

`X-API-Key` identifies the destination account. `Authorization` contains the
L402 payment proof. Keep both headers: payment proof alone cannot redirect a
purchase to a different account. Neither header belongs in a URL or log.

- **200**: `credited=true`. The response contains `credit_usd`, `balance_usd`
  and `currency=USD`. Credit was delivered, or was already delivered previously.
- **202**: settlement is pending. Honor `Retry-After` and retry the same request.
  Do not pay again. A preimage alone cannot mint credit without verified settlement.
- **400**: invalid amount, body or missing/malformed idempotency key.
- **401**: invalid/revoked destination key, or invalid/expired L402 proof.
- **409**: conflicting purchase parameters, an unresolved prior invoice, or an
  expired invoice. Do not issue another payment while the previous one is pending.
- **410**: the invoice is canceled. No new invoice is created by this retry.
- **429**: rate limited. Honor `Retry-After`.
- **503**: temporarily unavailable or payment needs review. Keep the key and
  purchase ID. The settlement worker continues recovering verified payments.
  Do not interpret this as a refund or permission to pay again.

L402 proofs expire 24 hours after invoice creation. That does not expire paid
credits. After token expiry, use the same key at https://lightningrouter.ai/usage
or recover the invoice through the existing key-authenticated funding API.
New invoices still have their own shorter payment/quote expiry.

## Inference is unchanged

Use `Authorization: Bearer <API key>` at https://api.trustedrouter.com/v1.
Do not send the L402 proof there. L402 funds prepaid USD credit; it does not grant
unlimited inference, bypass spending limits, or change the attested prompt path.
No BTCPay account is required. The funding endpoint uses the current receiving
backend, Lexe, and can reconcile invoices issued by the legacy LND backend.

Browser refresh, background reconciliation and repeated L402 redemption all use
the same payment-hash-bound credit ledger. A payment is credited at most once.
