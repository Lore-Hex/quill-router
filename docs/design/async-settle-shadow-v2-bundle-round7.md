# C2 round 7 working record

This remains a local, dormant package. No release result is claimed.

The production example uses actual package outputs for transport, pre-enable,
and closed warm-up on three separate dates. The warm-up retains the exact
reviewed pre envelope and its original file graph. Each predecessor descriptor
names its source root, bounded input plan, transport parts, release file, and
original evaluation. The package copies and recursively re-evaluates these
records. A window reviews the predecessor descriptors and their bounded input
plans instead of repeating every predecessor filename in one release file.
The complete files remain in the window input inventory.

The eight-date example selects seven elapsed days from an after-midnight sample
and retains two support dates. Each daily call uses real package producers over
fake source ports. Existing incomplete evaluator results stay incomplete.

The file-cost helper compares each output against its own reservation, rejects
extra or missing files and oversized files, and separates reserved bytes from
measured bytes. Only the following pass can consume a measured receipt record.
Daily collection returns the later-file record. This does not yet establish
complete accounting for every final review and report-writing path. Legacy
group ceilings are expanded from staged files; independently enumerated file
plans are supported but not yet mandatory at every public entry.

Nonempty retained history now has composed-path coverage. Its supporting
original is separately removed, replaced with another well-formed original,
and changed without updating its reference. The older full byte matrix is
retained; these additions do not claim that all requested semantic replacements
have been completed.

The local deployment defaults do not provide a finite daily launch bound and
first-window pass schedule. The runbook's `release/first-window-plan.json` is not
in this checkout. The existing padded allocation check measures the producer
and frozen-call boundaries separately, but does not establish the configured
largest day. P6 owns the released finite input record; C2 still owns generating
and measuring that day and completing the remaining semantic cases.
