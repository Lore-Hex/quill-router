How Magnitude runs local LLMs across GPU memory, RAM and SSD

Understand expert streaming, interpret Magnitude’s published Qwen benchmark, and decide when an SSD-backed model makes sense on your Mac or PC.

2026-11-24

A 24 GB graphics card can be too small to hold a model's weights and still be useful for running it. Magnitude takes advantage of a property of supported sparse mixture-of-experts models: each new token uses only a subset of the expert weights. The entire model must be accessible, but every expert need not occupy the fastest memory at the same time. Magnitude project

What happens when the model needs an expert?

Picture a desktop with an NVIDIA card, system RAM and an NVMe SSD. Magnitude keeps shared layers and frequently used experts close to the GPU, holds another set in RAM, and reads colder experts from storage. Its prefetcher tries to move the next weights into place while the GPU is busy. If it guesses well, some transfer time overlaps computation. When the needed weights arrive late, generation waits. Apple silicon uses unified memory, so a Mac's memory figure should not be counted once as RAM and again as separate VRAM. Project architecture and benchmarks

What does 41 tokens per second tell you?

In the launch post, Tom Greenwald reports 41 tokens per second for Qwen 3.8 Flash Next on an RTX 3090 with 64 GB of system RAM and a PCIe 4.0 SSD, under the post's 2-bit, 64k-context configuration. At that decode rate a 200-token answer would take roughly five seconds after generation begins. Loading the model and processing the input can add time before the first word appears. This is the project's reported result for that configuration. Greenwald’s launch post

Try a decision your own hardware can settle

Install the build for your operating system and choose a supported sparse model. Give it a representative task, such as explaining a short function with a known edge case. Record time to first word, total time and whether the answer catches the edge case. Repeat with a smaller model that fits comfortably in memory, then repeat with a long input. The smaller model may finish an interactive task sooner even when the larger model gives a better explanation.
